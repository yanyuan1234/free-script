BUG-028 修复详情（本轮核心修复）

BUG-028 已验证修复

问题描述：流式生成2-3分钟后，浏览器主线程完全冻结7分钟以上。之前在第2轮测试中，流式生成到达约2分钟时浏览器完全无响应。

根因分析：流式生成期间，当打字机追上流式输出速度（queue 耗尽 → pause() → isTyping=false），如果此时有新段落完成，TypewriterBuffer.render() 会走非打字路径，调用 formatStory(fullText) + innerHTML 全量替换。formatStory 的非打字路径包含 PresetAppManager.parseFromText + stripDecorTags + _cleanUnrecognizedTags + sanitizeHtml(DOMParser) + 完整 innerHTML DOM 重建，每次都是 O(n) 操作。长时间流式（2-3分钟）中此路径被触发数十次，每次处理逐步增长的文本，累积导致主线程冻结。

修复方案：在 TypewriterBuffer 中新增 _streamingMode 标志位。流式开始时设为 true，render() 在此标志为 true 时始终使用 O(1) 增量 appendChild 路径，不调用 formatStory 全量格式化。流式结束（_doFinalRender）时设为 false，让最终渲染走 formatStory 全量路径。

修改文件：

• js/core.js - TypewriterBuffer 新增 _streamingMode 字段，render() 条件判断修改，stop() 重置标志

• js/game.js - sendAIRequest 中设 _streamingMode = true，_doFinalRender 中设 _streamingMode = false

已修复问题（本轮）

BUG-029 已修复

问题描述：流式生成期间，文本渲染会出现短暂的字符重复现象（如"的的"、"透透"、"窗窗"），以及段落级别的文本重复。最终渲染完成后文本正常。

影响程度：低 —— 不影响最终显示结果，仅流式过程中可见

原因分析：BUG-028 修复后，流式期间使用增量 appendChild 路径渲染。当段落从"当前打字中"变为"已完成"时，旧的 <p class="story-typing-para"> 元素未被移除，与新追加的 <p class="story-completed-para"> 形成文本重复。

修复方案：在 core.js 的 render() 增量路径中，追加新完成段落前，先检查并移除旧的 _currentParaEl 元素。

BUG-030 已修复

问题描述：showCotPanel（思维链显示）设置在游戏启动后丢失。通过 JavaScript 设置 gameState.showCotPanel = true 后开始游戏，游戏状态重置时该值变回 undefined。

影响程度：中 —— 思维链面板不会自动显示

原因分析：startNewGame() 调用 resetRuntimeState('full') 时，createDefaultGameState() 替换了整个 gameState 对象，而新对象中不包含 showCotPanel 字段。之后未调用 loadGameSettings() 恢复用户保存的设置。

修复方案：1. createDefaultGameState() 中新增 showCotPanel: false 默认值；2. startNewGame() 在 resetRuntimeState('full') 之后调用 loadGameSettings() 恢复所有已保存设置。
