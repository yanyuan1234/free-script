二、Bug详细分析

BUG-012 严重 max_tokens自动计算值未传给API请求体
问题描述

第一轮修复了 getEffectiveMaxTokens() 从 wcMax 自动计算 max_tokens，但该值仅用于提示词文本，从未传递到 API 请求体。API 实际下发的 max_tokens 仍来自预设管理器的 presetParams.max_tokens（默认2048）。

根因

core.js:5959 中 API 请求体直接使用 presetParams.max_tokens，未调用 getEffectiveMaxTokens()。

修复
// core.js: API 请求体 - max_tokens: presetParams.max_tokens, + var _effectiveMaxTokens = (typeof getEffectiveMaxTokens === 'function') ? getEffectiveMaxTokens() : 0; + var _apiMaxTokens = _effectiveMaxTokens > 0 ? _effectiveMaxTokens : (presetParams.max_tokens || 4096); + max_tokens: _apiMaxTokens,
BUG-013 严重 原型卡片点击崩溃（方法不存在）
问题描述

点击任意原型卡片（.archetype-card）时调用 MemoryManagerUI.selectArchetype()，但该方法不存在，抛出 TypeError 导致功能完全不可用。

修复
- MemoryManagerUI.selectArchetype(card.dataset.archetype); + if (typeof applyArchetype === 'function') { + applyArchetype(card.dataset.archetype); + } else if (typeof _applyUnifiedPreset === 'function') { + _applyUnifiedPreset(card.dataset.archetype, { setArchetype: true }); + }
BUG-014 高 硬编码"800字"最低要求覆盖用户字数设置
问题描述

两处硬编码了"每回合剧情正文不少于800中文字符"作为强制要求，即使用户设置了较短的字数范围（如300-500字），AI仍会看到"强制要求至少800字"而忽略用户设置。这与第一轮的"硬编码第二人称"bug完全同一模式。

涉及位置

1. game.js:788 - _buildFormatRules 中的 story 长度强制要求
2. prompt-builder.js:167 - workflow 段中的叙事要求

修复

移除硬编码的800字要求，改为"根据用户设置的字数范围生成"。

BUG-015 高 buildRecentChatContext玩家消息标注"主角"代称
问题描述

与第一轮BUG-003同一模式。私聊记录中玩家消息被标注为"主角"而非真实姓名，导致AI在后续剧情中用"主角"代称玩家。

修复
- var who = ... ? '主角' : npcName; + var who = ... ? (gameState.playerName || '主角') : npcName;
BUG-016 高 memoryUpdates示例使用"主角"代称
问题描述

记忆更新契约的示例文本中使用"主角"代称玩家（如"主角答应帮林晚..."），AI会模仿示例格式，在永久记忆区中用"主角"而非真实姓名写入记忆。涉及 game.js:824 和 prompt-builder.js:222,224 两处。

修复

将示例中的"主角"替换为 gameState.playerName 或 ctx.protagonistSetup.mcName。

BUG-017 高 mcPersonality等字段未传到player data
问题描述

第一轮修复了 core.js 的字段映射（mcPersonality → setupPlayerDesc），但 initializeGame() 中从主角设定补全 player 数据时，只复制了 identity 和 age，遗漏了 personality、gender、appearance、ability。导致个人页在AI首次返回前无法显示用户填写的性格等信息。

修复
+ if (!_smPlayer.personality && gameState.protagonistSetup.mcPersonality) + _smPlayer.personality = gameState.protagonistSetup.mcPersonality; + if (!_smPlayer.gender && gameState.protagonistSetup.mcGender) + _smPlayer.gender = gameState.protagonistSetup.mcGender; + if (!_smPlayer.appearance && gameState.protagonistSetup.mcAppearance) + _smPlayer.appearance = gameState.protagonistSetup.mcAppearance; + if (!_smPlayer.ability && gameState.protagonistSetup.mcAbility) + _smPlayer.ability = gameState.protagonistSetup.mcAbility;
BUG-018 高 narrativeEyes/useStream/maxTokens/presetArchetype设置不持久化
问题描述

saveGameSettings() 通过 _sm('settings.xxx') 读取 StateManager settings 路径的值，但运行时这些字段被直接写入 gameState.xxx（顶层字段），两者是不同的对象。导致用户修改的叙事视角开关、流式输出、max_tokens等设置在刷新后恢复为默认值。

根因

StateManager.init() 执行 window.gameState = this._state 后，gameState.xxx = value 写入顶层，而 StateManager._state.settings.xxx 是 normalizeState() 时深拷贝的独立对象，不会同步更新。

修复

在 saveGameSettings 中优先从 gameState（顶层）读取这些字段，fallback 到 _sm()。

BUG-019 中 流式提取器状态变量未在请求间重置
问题描述

_resetStreamExtractor() 未重置三个惰性初始化的全局变量（_streamIsLikelyJSON、_streamJsonScanPos、_streamThinkScanPos），导致上一轮请求的残留状态污染当前请求，可能延迟内容显示。

修复
+ _streamIsLikelyJSON = undefined; + _streamJsonScanPos = 0; + _streamThinkScanPos = 0;
BUG-020 中 默认wordCountConfig缺少perspective字段
问题描述

core.js:4743 的兜底默认对象缺少 perspective 和 userPronoun 字段，若触发此兜底路径，formatReminder 会因 perspective 为空而走 else 分支，回退到第二人称。

修复
+ perspective: 'third_person_limited', userPronoun: 'third_person'
BUG-021~24 低 死代码引用（4处）
问题描述

以下4处引用了已被删除的元素/变量/方法，有 null 守卫不会崩溃，但属于死代码：

1. preset-manager.js:387 - 引用已删除的 settingStoryLength 元素
2. phone-ui.js:1084,1095,1096 - 引用已删除的 logFeat-author_note/logFeat-world/logFeat-memory 元素
3. stream-worker.js:165 - 引用已不存在的 _pendingChunkMsg 变量
4. phone-ui.js - saveGameSettings 残留 chapterMode 读取

修复

移除所有死代码引用。stream-worker.js 的 _pendingChunkMsg 已修复，其余已有 null 守卫不会造成功能影响。
