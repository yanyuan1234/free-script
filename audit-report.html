二、Bug详细分析

BUG-001 严重 设置第三人称但AI始终使用第二人称叙事
问题描述

用户在游戏设置中选择了"第三人称有限"视角，但AI生成的剧情始终使用"你"（第二人称）叙事，完全无视用户设置。

根因分析

在 game.js:1885 中，格式提醒被硬编码为始终使用第二人称，直接覆盖了用户在设置页面选择的视角：

// 硬编码的第二人称，无视用户设置 - _formatReminder += '\n始终使用第二人称（"你"）叙事。';

此外，injectPresetGlobalVars() 中的 perspectiveMap 缺少 second_person 的映射，导致宏变量"叙述视角"无法正确注入。

修复方案
// 【修复】根据用户设置动态决定人称，不再硬编码第二人称 + var _wcConfig = (gameState && gameState.wordCountConfig) || {}; + var _perspective = _wcConfig.perspective || ''; + var _userPronoun = _wcConfig.userPronoun || ''; + var _personRule = ''; + if (_perspective === 'third_person_limited' || _perspective === 'third_person_omniscient') { + _personRule = '始终使用第三人称叙事，用角色名字或"他/她"指代主角。'; + } else if (_perspective === 'first_person_limited') { + _personRule = '始终使用第一人称叙事，用"我"指代主角。'; + } else if (_userPronoun === 'third_person') { + _personRule = '用第三人称（名字或"他/她"）指代主角。'; + } else if (_userPronoun === 'first_person') { + _personRule = '用第一人称"我"指代主角。'; + } else { + _personRule = '始终使用第二人称（"你"）叙事。'; + } + _formatReminder += '\n' + _personRule;

同时在 injectPresetGlobalVars() 中补充了 second_person 的映射。

BUG-002 严重 字数设置1500-3000但AI只生成几百字
问题描述

用户在字数控制中设置了最低1500字、最高3000字，但AI实际只生成了约800字。控制台日志显示 sanitizeStory: 0.1ms (len=781)，远低于预期。

根因分析

问题有两层：

1. max_tokens不足：中文字符约需要2个token，生成3000字需要约6000+ token。但 getEffectiveMaxTokens() 的默认值为2048，远不够支撑3000字的输出。原有的"参数设置"卡片中的 settingStoryLength 也默认为2048。

2. 两套字数系统冲突：存在"参数设置"卡片的 max_tokens 和"字数控制"卡片的 wcMin/wcMax 两套系统，互不同步。用户设置了字数控制但 max_tokens 仍是默认值，导致AI在token层面被截断。

修复方案
// 【修复】max_tokens 由 wcMax 自动计算，不再需要手动设置 + var wcMax = (wcConfig.max || 3000); + // 中文字符约需要2个token，加20%余量 + var autoMaxTokens = Math.ceil(wcMax * 2.4); + // 确保最小2048 + var effective = Math.max(autoMaxTokens, 2048); + return Math.min(effective, 32000);

同时删除了"参数设置"卡片（含 settingStoryLength 控件），消除两套系统冲突。max_tokens 现在完全由字数控制的 wcMax 自动推导。

BUG-003 严重 个人页面主角姓名显示为"主角"而非真实姓名
问题描述

用户创建角色时输入了姓名"林逸辰"，但个人页面和关系网中主角的名称显示为"主角"而非真实姓名。AI在关系网中也使用"主角"代称。

根因分析

在 game.js:804 中，AI指令明确告诉模型使用"主角"二字而非真实姓名：

- ...主角用"主角"二字。**有NPC互动时每回合必须返回 relationships...**

这导致AI在 relationships 数据中始终使用"主角"作为主角名称，而非用户输入的真实姓名。

修复方案
+ ...主角使用真实姓名"' + (gameState.playerName || '主角') + '"而非代称。 + **有NPC互动时每回合必须返回 relationships...**
BUG-004 严重 个人页面基本信息未显示（字段映射错误）
问题描述

个人页面中主角的性格、额外信息等基本信息为空，未正确显示。

根因分析

在 core.js:7527 中，角色创建时的字段映射引用了不存在的HTML元素ID：

// 错误的映射：引用了不存在的HTML元素 - mcPersonality: 'setupPlayerPersonality', // HTML中不存在此ID - mcExtra: 'setupPlayerExtra' // HTML中不存在此ID // 实际HTML中存在的ID是： // setupPlayerDesc - 角色描述/性格 // setupPlayerAppearance - 外观 // setupPlayerAbility - 能力

由于 document.getElementById() 对不存在的ID返回 null，导致性格和额外信息无法被读取，最终不进入游戏状态。

修复方案
+ mcPersonality: 'setupPlayerDesc', // 修正为正确的HTML ID + // mcExtra 已移除（setupPlayerExtra 不存在）
BUG-005 高 思维链（思维链面板）未在剧情页面显示
问题描述

用户在设置中开启了思维链模式（cotMode = enabled），但剧情页面中始终看不到思维链面板。控制台日志显示 [COT] 提取到思维链内容: 0 段标签 + 1 段 reasoning_content，说明思维链数据已提取，但面板未显示。

根因分析

存在三个关联问题：

1. showCotPanel 从未被设置：CotPanelController.showPanel 的 getter 要求 gameState.showCotPanel === true，但在设置 cotMode 时从未同步设置 showCotPanel。

2. 旧逻辑冲突：game.js:2355 中旧的渲染逻辑默认 _showCot = true，但 CotPanelController.show() 内部使用新的 showPanel 判断，两者逻辑不一致。

3. 加载时不恢复：loadGameSettings() 中恢复了 cotMode 但未同步 showCotPanel，刷新后设置丢失。

修复方案

修复1 - settingCotMode 变更时同步 showCotPanel：

+ // phone-ui.js: settingCotMode change handler + gameState.showCotPanel = (this.value === 'enabled'); + gameState.cotMode = this.value;

修复2 - showPanel getter 同时检查 cotMode：

+ // phone-ui.js: CotPanelController.showPanel getter + if (gameState.showCotPanel === true) return true; + if (gameState.cotMode === 'enabled') return true;

修复3 - 加载设置时同步 showCotPanel：

+ // phone-ui.js: loadGameSettings() + gameState.showCotPanel = (d.cotMode === 'enabled');

修复4 - 统一 game.js 中的显示判断逻辑：

// game.js: 使用 CotPanelController.showPanel 统一判断 - var _showCot = true; + var _showCot = false; + if (typeof CotPanelController !== 'undefined' && CotPanelController.showPanel) { + _showCot = true; + }
BUG-006 高 关系网中AI使用代称（学霸/小少爷）而非真实姓名
问题描述

用户在角色设定中使用统称（如"小少爷"、"学霸"）来描述NPC，但AI在生成剧情和关系网时也使用了这些代称，而非为NPC生成真实姓名。

根因分析

AI指令中缺少明确要求"为NPC使用真实姓名而非代称"的规则。模型倾向于直接使用用户提供的描述词作为名称。此外，主角也使用"主角"代称（见BUG-003），进一步强化了使用代称的模式。

修复方案

在关系网指令中明确要求主角使用真实姓名（BUG-003的修复），同时这是AI提示工程的通用问题——需要在 system prompt 中增加"为每个NPC赋予真实姓名"的规则。当前修复已确保主角姓名正确，NPC命名问题建议在后续版本中通过增强 prompt 解决。

BUG-009 中 设置页面"参数设置"卡片与字数控制、预设管理器大量重复
问题描述

游戏设置页面存在严重的功能重复：

- "参数设置"卡片中的"剧情长度(max_tokens)"与"字数控制"卡片的 wcMax 功能重叠

- "参数设置"卡片中的快捷预设按钮与"预设管理器"功能完全重复

- "字数控制"卡片中的"叙述视角(wcPerspective)"和"user代词(wcUserPronoun)"两个控件功能重叠，容易导致冲突

- "叙事增强"卡片中的"写作节奏(settingChapterMode)"与"字数控制"中的"段落风格(wcParagraphStyle)"功能重复

修复方案

1. 删除整个"参数设置"卡片（含 settingStoryLength、快捷预设按钮、精细调参入口）—— max_tokens 改由 wcMax 自动计算，精细参数由预设管理器统一管理。

2. 合并叙述视角和user代词为单一的"叙述人称"下拉框，选项包括：第三人称（他/她）、第三人称全知、第二人称（你）、第一人称（我）。userPronoun 由 perspective 自动推导，不再需要独立控件。

3. 删除"写作节奏(settingChapterMode)"控件——与段落风格功能重复。

4. 将演绎授权、转述授权、推进节奏从"字数控制"卡片移至"叙事增强"卡片，字数控制只保留纯字数相关的控件。

BUG-010 中 设置页面人称控件过多导致判定冲突
问题描述

设置页面原本存在两套人称控制系统：wcPerspective（叙述视角）和 wcUserPronoun（user代词），两者功能高度重叠。用户可能在一个控件选择第三人称，在另一个控件选择第二人称，导致最终行为不确定。

根因分析

wcPerspective 控制叙事视角（第三人称有限/全知、第一人称），wcUserPronoun 控制主角代词（你/他/她/我）。但这两个维度在实际使用中是耦合的——选择第三人称视角自然意味着用"他/她"指代主角，不需要两个独立控件。

修复方案

合并为单一"叙述人称"控件。userPronoun 由 perspective 自动推导：

// phone-ui.js: saveGameSettings() 中自动推导 + userPronoun: (function() { + var _p = document.getElementById('wcPerspective').value; + if (_p === 'second_person') return 'second_person'; + if (_p === 'first_person_limited') return 'first_person'; + return 'third_person'; + })()

同时移除了所有读取 wcUserPronoun 控件值的代码，以及 HTML 中的 wcUserPronoun select 元素。

BUG-011 中 injectPresetGlobalVars 缺少 second_person 映射
问题描述

宏变量"叙述视角"和"char代词"的映射表中缺少 second_person 选项，导致当用户选择第二人称时，宏变量无法正确注入。

修复方案
// game.js: injectPresetGlobalVars() + 'second_person': '叙述视角：第二人称', // perspectiveMap + 'second_person': '你', // charPronouns
