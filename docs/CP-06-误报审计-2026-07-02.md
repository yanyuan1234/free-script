# CP-06 STScript 引擎误报审计

**审计日期**：2026-07-02
**审计结论**：**误报（无需修复）**——slash command 引擎 100% 完整

---

## 1. 误报来源

综合审查统筹版第 7 章将 **CP-06** 标记为 P0 极高风险任务：

> **CP-06** STscript 引擎被砍 → 0 slash command 注册（backup 60+ 命令全失）

**审计证据**：报告基于单一文件 `js/ai-contract/stscript-bridge.js` 的检查，得出"0 slash command 注册"结论。但 slash command 引擎实际位于 `js/tavern-compat.js`，属另一模块。

## 2. 架构事实

| 组件 | 位置 | 职责 |
|------|------|------|
| **STscript Bridge** | `js/ai-contract/stscript-bridge.js` | **桥接层**：将酒馆生态（PresetManager / RegexManager）的状态变更同步到游戏世界；**不**负责 slash command 注册 |
| **TavernHelperCompat** | `js/tavern-compat.js:114-789` | **slash command 引擎**：包含 registerSlashCommand、triggerSlash、_executeSingleCommand、_loadPresetConfigs、window.SillyTavern shim |

**设计意图**：单文件 33k+ 行的 `backup/index.html` 拆分到多文件后，按职责分离：
- `tavern-compat.js` 拥有酒馆兼容核心（含 slash command 引擎）
- `stscript-bridge.js` 仅保留**桥接**（hook PresetManager/RegexManager）

## 4. 误报根源分析

报告生成时，分析子代理可能只 grep 了 `stscript-bridge.js` 这一个文件。看到该文件 0 个 `registerSlashCommand` 调用就下结论"60+ 命令全失"。

**这与之前 P0-7（buildAIRequestBody 缺 6 参数）、P0-8（data-args XSS）的误判同源**：只看了表层文件就下结论，没有跨文件交叉验证。

## 5. 改进建议

为防止类似误报再发，已在 `stscript-bridge.js` 文件头添加**职责边界**注释，标明 slash command 引擎的实际位置。

**CP-06 不是 bug，是架构拆分后的正常状态**。slash command 引擎完整无缺：

- ✅ `window.SillyTavern` shim 完整（getContext / getCharacters / saveChat / generateRaw / on/emit 等）
