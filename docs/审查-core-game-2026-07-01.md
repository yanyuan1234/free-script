## 1. P0 — 必修

### P0-1 `isModelFailed` key 格式不匹配 → 失败模型追踪失效

**位置**：`/workspace/js/core.js:1217-1231`
```javascript
function isModelFailed(modelName) {
    if (!modelName) return false;
    var failedAt = _failedModels[modelName];  // <-- 读 modelName
    if (!failedAt) return false;
    if (Date.now() - failedAt > _MODEL_FAILURE_TIMEOUT) {
        delete _failedModels[modelName];
        return false;
    }
    return true;
}
```

**调用点（`/workspace/js/phone-ui.js:5198`）**：
```javascript
if (LocalGameAPI.isModelFailedForSlot(slotKey)) { ... }
```

**问题**：写入用 `slotKey`（如 `chat/api/gpt-4`），读取用 `modelName`（如 `gpt-4`），**两者 key 不一致**，导致 `isModelFailed` 永远返回 `false`，失败模型追踪完全失效。每次失败都会重试同一模型，浪费配额。

**酒馆 API 对齐**：酒馆助手的"轮换模型"依赖 `isModelFailed` 决定是否跳过当前模型；key 不匹配意味着酒馆的轮换语义不生效。

**修复方案**：
```javascript
// 统一使用 slotKey 维度
_failedModels[slotKey] = Date.now();
function isModelFailed(slotKey) { ... }
```

### P0-2 `window._currentAbort` 跨文件全局可变状态 → 取消逻辑不可靠

**位置**：`/workspace/js/core.js`（`window._currentAbort = controller;` 出现多次）
**触发**：`/workspace/js/game.js:1300-1310`
```javascript

... // 实际调用
```

**问题**：

**修复方案**：
```javascript
// 改为局部变量 + 闭包
function sendAIRequest(messages) {
    const controller = new AbortController();
    // ... 传递 controller.signal 给 callAI
}
```

### P0-3 `buildAIRequestBody` 缺失酒馆关键参数

**位置**：`/workspace/js/core.js:4500-4600`（节选）
```javascript
function buildAIRequestBody(messages, options) {
    var body = {
        model: currentModel,
        messages: messages,
        temperature: ...,
        max_tokens: ...,
        stream: options.stream || false
    };
    // 缺：top_p, frequency_penalty, presence_penalty, stop
}
```

**酒馆 API 文档**：
```typescript
// 酒馆标准请求
{
    model: string,
    messages: ChatMessage[],
    temperature?: number,
    top_p?: number,
    frequency_penalty?: number,
    presence_penalty?: number,
    max_tokens?: number,
    stream?: boolean,
    stop?: string | string[]
}
```

**问题**：
1. **`top_p` 未透传** → 用户在 UI 调整 top_p 实际不生效。
2. **`frequency_penalty` / `presence_penalty` 未透传** → 重复惩罚策略失效。

4. **`model` 字段不响应运行时切换** → 用户切换模型后仍按旧模型发请求（取决于 `_getCurrentModel` 实现，需进一步确认）。

```javascript
    messages: messages,
    temperature: options.temperature ?? PresetManager.currentParams.temperature,
    top_p: options.top_p ?? PresetManager.currentParams.top_p,
    frequency_penalty: options.frequency_penalty ?? PresetManager.currentParams.frequency_penalty,
    presence_penalty: options.presence_penalty ?? PresetManager.currentParams.presence_penalty,
    max_tokens: options.max_tokens ?? 4096,
    stream: options.stream || false,
    stop: options.stop || null
};
```

### P0-4 `SaveDB._attachChecksum` 每次 autoSave 深克隆 → 性能问题

**位置**：`/workspace/js/core.js:1559-1580`
```javascript
_saveDB: function() {
    var data = JSON.parse(JSON.stringify(this.data));  // <-- 深克隆
    data._checksum = this._computeChecksum(data);
    localStorage.setItem(this._key, JSON.stringify(data));
}
```

**问题**：
- `autoSave` 默认每 2 秒一次（来自 `SaveDB.startAutoSave` 推断）。
- `this.data` 包含 `gameState`（含 `conversationHistory`、`characters`、`longTermMemory` 等），典型 100KB-1MB。
- 每次 `JSON.parse(JSON.stringify(...))` 浪费 O(N) 内存 + 两次序列化。
- 写入 `localStorage` 同步阻塞主线程，长剧情卡顿。

**酒馆 API 对齐**：酒馆使用 IndexedDB（异步），不阻塞。

**修复方案**：
```javascript
// 选项 1: 只对关键字段计算 checksum
function _computeChecksumSelective(data) {
    return fastHash(JSON.stringify({
        cid: data.currentChapterId,
        hist: data.conversationHistory?.length,
        ts: Date.now()
    }));
}
// 选项 2: 迁移到 IndexedDB（异步）
```

### P0-6 `extractSetupToMemory` 对 `gm.tables` 与 `mutator` 双写

**位置**：`/workspace/js/core.js:5395-5480`（推断行号，因代码块较长）
```javascript
function extractSetupToMemory(setup) {
    if (typeof gm !== 'undefined' && gm.tables) {
        gm.tables.set('setup', setup);  // 写入 A
    }
    if (typeof mutator !== 'undefined') {
        mutator.appendWorldNote(setup);  // 写入 B
```

**问题**：
- `gm.tables` 和 `mutator.appendWorldNote` 是两个独立的状态层。

**酒馆 API 对齐**：酒馆的世界书（World Info）只对应一个存储入口（`world_info` 数组），双写会破坏酒馆世界书加载顺序。

**修复方案**：
- 选定 `mutator` 为单一写入点，`gm.tables` 仅作缓存（每次从 `mutator.getWorldNotes()` 重建）。

### P1-5 `translateError` 的 HTTP_STATUS 与 API_CODE 表内容 90% 重复

**位置**：`/workspace/js/core.js:3815-4000`（推断）
```javascript
var HTTP_STATUS = {
    401: '未授权',
    429: '请求过于频繁',
    500: '服务器错误',
    502: '网关错误',
    503: '服务不可用'
};
var API_CODE = {
    'invalid_api_key': 'API Key 无效',
    'rate_limit': '请求过于频繁',
    'context_length_exceeded': '上下文超长',
    // 90% 与 HTTP_STATUS 描述相同

```

**问题**：
- 两份表 + 两个翻译函数。
- 当出现新错误时（如 404 Not Found），需要查 HTTP_STATUS 但表里没有 → fallback 到 "未知错误"，用户看到的错误信息不友好。
- 错误码映射残缺：缺少 403（Forbidden，常因 Region/CORS）、404（Model not found）。

**修复方案**：
```javascript
const ERROR_TABLE = {
    http: { 401: '...', 403: '...', 404: '...', 429: '...', 500: '...', 502: '...', 503: '...' },
    api: { 'invalid_api_key': { status: 401, msg: '...' }, 'rate_limit': { status: 429, msg: '...' } }
};
function translateError(err) {
    const status = err.status || err.response?.status || ERROR_TABLE.api[err.code]?.status;
    return ERROR_TABLE.http[status] || err.message;
}
```

### P1-6 `parseMarkdown` 不转义 HTML → XSS

**位置**：`/workspace/js/core.js:4015-4210`（推断）

```javascript
function parseMarkdown(text) {
```

```javascript
}
function parseMarkdown(text) {
    return escapeHtml(text)  // 先转义
        .replace(/\*\*(.+?)\*\*/g, '<strong>$1</strong>')
        // ... 其它规则
        ;
}
```
