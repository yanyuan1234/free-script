## 一、项目定位

Free-Script 是一个**个人自用的 AI 文字冒险 / 互动小说游戏**。

核心体验：玩家输入世界观设定，AI 逐回合生成剧情和选项，玩家通过选择或自定义行动推进故事。一次游戏可达上百回合、几十万字，本质上是人机协作创作长篇小说。

技术栈：纯静态 HTML + CSS + JavaScript，部署在 GitHub Pages，AI 通过 OpenAI 兼容 API 接入，数据存在 localStorage / IndexedDB。

### 1.1 为什么做这个游戏

用户玩不惯 SillyTavern（酒馆）的界面，所以自己做一个更符合个人习惯的移动端优先文游前端。

### 1.2 最高原则

- **质量优先**：用户接受慢，不接受烂。所有 bug 都不可忍。
- **个人自用**：不需要商业化，但体验要对标成熟产品。
- **文档先行**：先写清楚再实现，避免补丁堆补丁。
- **分阶段推进**：每阶段结束必须可运行，不追求一次性重写。

## 二、参考项目深度研究

### 2.1 SillyTavern（酒馆）

**定位**：PC 端最强大的开源 AI 角色扮演前端。

**核心设计**：
- 客户端-服务端架构（Node.js + 浏览器）。
- 状态分层：`characters[]`（角色卡）、`chat[]`（对话历史）、`this_chid`（当前角色ID）。
- Prompt 模板化：用模板系统组合 system prompt、角色描述、世界书、聊天记录。
- World Info（世界书）：按关键词检索注入 lore。
- 扩展框架：绘图、语音、翻译、记忆、向量检索等都是扩展。
- 角色卡格式：PNG V2/V3，内嵌 JSON。

**值得学习的地方**：
1. 对话历史与角色/世界状态严格分离。
2. Prompt 模板化，不是字符串拼接。
3. 世界书检索式注入，不塞全文。
4. 扩展/插件架构，功能可插拔。

### 2.2 MiniTavern / 手机酒馆AI

**定位**：SillyTavern 的官方移动端伴侣应用。

**核心功能**：
- 兼容 SillyTavern PNG 角色卡。
- 支持 OpenAI / Claude / Gemini / Grok / OpenRouter / Ollama。
- 角色导入、自定义、多角色对话。
- 剧情模式（预设故事弧线）。
- 本地优先，隐私优先。
- 导出聊天记录到 Markdown / Word / HTML。

**值得学习的地方**：
1. 移动端优先的 UI 设计。
2. 角色卡生态的利用。
3. 剧情模式（适合长篇小说式推进）。
4. 聊天记录导出功能。

### 2.3 NativeTavern

**定位**：Flutter 原生跨平台酒馆替代品，兼容 SillyTavern。

**核心功能**：
- 支持 PNG V2/V3、CharX、JSON 角色卡。
- 群聊、分支对话、世界书、正则脚本、宏命令。
- 本地数据 + 备份导出。

**最值得学习的点**：
- **分支对话（Message Branching）**：每条 AI 回复可以重新生成并保留旧版本，用户可前后切换。相当于对话历史的 Git 分支。
- 这个设计对 Free-Script 极其重要：当 AI 生成出"运转灵力"或剧情回退时，可以直接回滚到上一分支。

### 2.4 轻酒馆 Light Tavern（开源）

**定位**：NGA 网友用 AI 编程做的开源移动端酒馆，技术栈与 Free-Script 最接近。

**核心功能**：
- 纯前端独立运行，可用 Capacitor 打包为 Android APK。
- SSE 流式输出 + 打字机效果。
- **思维链折叠**：DeepSeek 的 reasoning_content 单独显示。
- **消息分支**：支持多分支对话，前后切换浏览。
- **重新生成**：保留旧回复、创建分支、自动切换到新分支。
- **编辑重发**：编辑已发送消息后重新生成 AI 回复。
- 角色卡 PNG 导入、世界书、正则脚本、ST 宏。
- **上下文总结**：一键生成摘要，折叠展示。
- **Token 优化**：有摘要时只发最近 20 条，无摘要发 40 条。
- **推荐回复**：AI 根据语境生成 3 条回复建议。

**最值得学习的点**：
1. **上下文总结 + token 优化**：解决 Free-Script 第 5 轮 11209 token 接近上限的问题。
2. **推荐回复**：给玩家选项的同时保留自定义输入。
3. **消息分支 + 重新生成**：完美的错误恢复机制。
4. **编辑重发**：玩家可以修改自己的上一条消息让 AI 重新续写。
5. 正则脚本清理 AI 输出。

### 2.5 RisuAI（开源）

**定位**：Svelte + TypeScript 写的跨平台开源 AI 角色扮演前端。

**核心设计**：
- 插件化架构（`src/ts/plugins/`）。
- 长期记忆、正则处理、多模态输入。
- 多 API 支持。
- 响应式 UI，桌面/移动组件分离。

**值得学习的地方**：
1. 插件化/模块化架构（对应 Free-Script 阶段 3）。
2. 长期记忆的实现方式。
3. 正则和脚本作为一等公民。

### 2.6 Mufy / MufyAI

**定位**：商业化 AI 情感陪伴/角色扮演应用（闭源）。

**核心功能**：
- 100+ 预设角色，分类筛选。
- 深度角色定制：外观、性格、背景故事、语音。
- 永久记忆：AI 记住对话细节、偏好、梗。
- 剧情模式："角色故事线"按章节推进。
- 语音/图片双模态。

**值得学习的地方**：
1. "剧情模式"和"角色故事线"的产品化思路。
2. 永久记忆的 UX 设计。
3. 移动端沉浸感设计。

## 五、分阶段路线图

### 阶段 1：统一状态层（State Abstraction Layer）

**目标**：让 `gameState` 成为单一事实来源，所有状态读写走 `StateManager` API。

**关键产出**：
- `js/state/schema.js`
- `js/state/state-manager.js`
- `js/state/mutators/`（bag / quest / character / time）
- `js/state/adapters/`（game-memory / save）
- `index.html` 加载顺序调整
- 关键路径迁移：bag、quests、characters、time、progress、ui

**解决 bug**：
- 物品 undefined
- 任务状态 pending
- 状态不同步
- 地点数始终为 0
- 日志子页面路由竞争（UI 状态分离）

**验收标准**：
1. 新建游戏、选择、剧情推进正常。
2. 连续 5 轮无剧情回退、状态丢失。
3. 物品页面无 undefined。
4. 任务状态全中文。
5. 地点字段启用。
6. 存档读档正常。

### 阶段 2：AI 输出契约层（AI Contract Layer）

**目标**：在 AI 和 UI 之间建立强边界：Prompt 模板化、输出 Schema 校验、后处理流水线、失败回退。

**关键产出**：
- `js/ai/prompt-builder.js`：模板化 prompt 构建
- `js/ai/response-parser.js`：JSON / 纯文本解析，Schema 校验
- `js/ai/fallback-engine.js`：选项/标题/状态回退生成
- `js/ai/output-sanitizer.js`：HTML 转义、cursor 清理、引号修复
- `js/ai/context-manager.js`：滚动摘要、token 预估、裁剪策略
- `js/ai/worldbook-retriever.js`：检索式世界书注入

**解决 bug**：
- 选项退化（运转灵力）
- 标题更新不一致
- 光标符号残留
- HTML 标签泄露
- "核心规则 undefined 条"
- 第 5 轮生成耗时 >100s

**验收标准**：
1. 末日生存主题下，选项不再出现修仙/武侠词汇。
2. 流式输出结束时无光标残留。
3. 故事中无未闭合 HTML 标签。
4. 第 10 轮生成耗时 <60s。
5. 控制台无 undefined 错误。

### 阶段 3：模块拆分与架构整理

**目标**：把单体文件拆分为职责清晰的模块，建立插件/扩展雏形。

**关键产出**：
- `js/engine/story-engine.js`：剧情推进核心
- `js/engine/choice-engine.js`：选项生成与验证
- `js/ui/renderer/`：UI 渲染器拆分
- `js/features/branches.js`：消息分支系统
- `js/features/character-cards.js`：角色卡导入/导出
- `js/features/chapter-archive.js`：剧情章节归档

**解决/新增能力**：
- 文件过大问题
- 消息分支/重新生成
- 角色卡生态
- 剧情章节归档

**验收标准**：
1. 没有文件超过 2000 行。
2. 可以重新生成某轮回复并切换版本。
3. 可以导入 SillyTavern PNG 角色卡。
4. 可以按章节回顾剧情。

### 阶段 4：测试与回归体系

**目标**：建立自动化测试，确保不再"修一个出三个"。

**关键产出**：
- 单元测试：`tests/unit/state-manager.test.js` 等
- 集成测试：模拟 AI 返回的状态解析流程
- 回归测试：5 轮/20 轮游戏脚本
- GitHub Actions 自动跑测试

**验收标准**：
1. 每次提交前测试通过。
2. 新增功能必须有对应测试。
3. 回归测试覆盖 P0/P1 全部 bug。

2. **读阶段 1 spec**（`docs/superpowers/specs/2026-06-22-state-layer-design.md`）。
3. **查看当前进度章节**，确认哪些已完成、哪些进行中。
4. **不要直接修 bug**：先确认该 bug 属于哪个阶段，在对应阶段内解决。
5. **不要扩大范围**：如果当前在做阶段 1，不要顺手改 prompt 或选项生成。
6. **修改后必须运行 `node --check js/<file>.js` 验证语法**。
7. **修改后必须更新本文档的"当前进度"章节**。
8. **提交前必须手动部署**（见 `docs/00-项目总览.md` 或 `.trae/rules/project_rules.md`）。

## 十、用户偏好记录
