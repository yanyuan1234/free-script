### 1.1 P0：parsePreset 对酒馆 V4 (openai_prompts) 格式不识别 [P0]

**位置**：`/workspace/js/modules/preset-manager.js:433-829`

**代码片段**：
```javascript
parsePreset: function(data, fileName) {

    var importedPrompts = [];
```

**酒馆子系统对齐说明**：
SillyTavern 自 1.13+ 引入 OpenAI 风格预设（`openai_prompts` 字段），与经典 `prompts` 并存。V4 预设结构为：
```json

  "prompt_order": [...],
  "prefer_character_prompt": true
```

当前实现完全忽略 `openai_prompts`，导致新版酒馆预设导入后只加载了半套提示词。

**修复方案**：
```javascript
// 在 prompts 处理后追加：
if (data.openai_prompts && Array.isArray(data.openai_prompts)) {
    data.openai_prompts.forEach(function(p) {
        if (!p || !p.content) return;
        importedPrompts.push({
            identifier: p.name || '',
            name: p.name || '',
            role: p.role || 'system',
            content: p.content,
            injection_position: 0,
            injection_depth: 4,
            system_prompt: (p.name === 'main'),
            enabled: p.enabled !== false,
            forbid_overrides: !!p.forbid_overrides
        });
    });
}
```

### 1.3 P1：parsePreset 未处理 `prompt_order` 中 `character_id != 100000` 的分组 [P1]

**位置**：`/workspace/js/modules/preset-manager.js:9-15, 514-533`

**代码片段**：
```javascript
function _findPromptOrderGroup(data) {
    if (!data || !data.prompt_order || !Array.isArray(data.prompt_order) || data.prompt_order.length === 0) {
        return null;
    }
    return data.prompt_order.find(function(g) { return g && g.character_id === 100000; })
        || data.prompt_order.find(function(g) { return g != null; });
}
```

**酒馆子系统对齐说明**：
酒馆 V3/V4 中 `prompt_order` 数组可能包含多个分组，分别对应不同的 `character_id`（单聊角色 ID、`100000`=全局、组聊、其他角色）。当前实现只取 `100000`（全局）或第一个非空分组，**未按当前加载角色 ID 匹配对应分组**。这导致角色级 `prompt_order` 排序被丢弃。

**修复方案**：
```javascript
function _findPromptOrderGroup(data, currentCharId) {
    if (!data || !data.prompt_order) return null;
    // 优先级：当前角色 ID > 100000（全局）> 第一个非空
    if (currentCharId) {
        var match = data.prompt_order.find(function(g) { return g && g.character_id === currentCharId; });
        if (match) return match;
    }
    return data.prompt_order.find(function(g) { return g && g.character_id === 100000; })
        || data.prompt_order.find(function(g) { return g != null; });
}
```

### 3.1 P0：缺失 `{{idle_duration}}` / `{{lastMessageId}}` / `{{mesId}}` 三个核心酒馆宏 [P0]

- `{{mesId}}` - 当前消息的 ID（数字）。

```javascript
text = text.replace(/\{\{idle_duration\}\}/gi, function() {
    var lastTime = (typeof gameState !== 'undefined' && gameState._lastMessageTime) || 0;
    if (!lastTime) return '0 minutes';
    var diff = Date.now() - lastTime;
    var mins = Math.floor(diff / 60000);
    if (mins < 1) return 'just now';
    if (mins < 60) return mins + ' minute' + (mins > 1 ? 's' : '');
    var hrs = Math.floor(mins / 60);
    if (hrs < 24) return hrs + ' hour' + (hrs > 1 ? 's' : '');
    return Math.floor(hrs / 24) + ' day' + (Math.floor(hrs / 24) > 1 ? 's' : '');

});
```

### 3.2 P1：process() 是 O(n*m) 重复扫描，应 tokenize 后分发 [P1]

**位置**：`/workspace/js/modules/macro-engine.js:682-911`

**问题说明**：
`process()` 函数对同一段文本执行了 **40+ 次** `text.replace(/.../gi, ...)`。每次都重新扫描整段文本，复杂度为 O(N × M × K)，其中 N=文本长度、M=正则数（40+）、K=宏出现次数。对于一个含 50+ 宏的预设 prompt（常见），处理时间会达到 O(N × 2000+)。

**修复方案（推荐）**：
```javascript
// 一次性扫描所有 {{...}} 占位符
process: function(text, env) {
    // ... preEnv 部分保留
    // 主循环用单次正则扫描
    var MACRO_PATTERN = /\{\{([\s\S]+?)\}\}/g;
    text = text.replace(MACRO_PATTERN, function(match, body) {
        return self._dispatchMacro(body.trim(), env) || match;
    });
    return text;
},

_dispatchMacro: function(body, env) {
    // 用分发表 O(1) 路由
    if (body.startsWith('user ')) return env.user || this.getUser();
    if (body.startsWith('char ')) return env.char || this.getChar();
    if (body === 'time') return this.time();
    // ... 等
    if (/^setvar::/.test(body)) return this._setvar(body);
    // 未知宏返回 null，调用方保持原样
    return null;
}
```

## 10. 总结

本次审查发现 **2 个 P0 问题、14 个 P1 问题、12 个 P2 问题、5 个 P3 问题**。

**P0 两个必修问题**：
1. `parsePreset` 未识别酒馆 V4 的 `openai_prompts` 字段；
2. `process()` 缺失 `{{idle_duration}}` / `{{lastMessageId}}` / `{{mesId}}` 三个核心酒馆宏。

**P1 必修问题 14 个**，主要分布于：
- 酒馆助手 `SPreset.Variable` 字段未解析
- 角色级 `prompt_order` 分组未匹配
- 酒馆 `sampler_order` / `logit_bias` / `custom_variables` 未识别
- regex `apply()` 的 placement 数字语义反了
- 酒馆 `substituteRegex=3` 未支持
- macro 的 `getUser` / `getChar` 等缺少完整 typeof 守卫
- `parseTheaterContent` 多个 type 冲突
- `SmartConfigEngine` applyConfig 完全缺失，行为与命名严重不符

**P2 清理问题 12 个**（部分已在文档中标记为死字段），建议下次重构时一并处理：
- preset-manager.js 中 6 个 `gameState._xxxConfig` 字段无消费者；
- smart-config-engine.js 的 `currentConfig` 字段无读者；
- 多处魔法数字（30/50）应提取为常量。

**死代码**：
- 1 个真实死字段组（`_theaterConfig` 等 6 个 gameState 字段）
- 1 个真实死字段（`SmartConfigEngine.currentConfig`）
- 没有完全未使用的方法（grep 验证）

**酒馆预设兼容性**：~85% 字段映射正确，3 个 P0/P1 必修问题修复后可达 95%。

**酒馆宏兼容性**：~90% 宏已实现，3 个 P0 必修宏修复后可达 95%。

**酒馆正则兼容性**：~80% 选项支持，placement 数字语义 bug 修复后可基本对齐酒馆行为。

**SmartConfigEngine**：当前为空壳，报告属实，需要实现 applyConfig 才能称为"配置引擎"。
