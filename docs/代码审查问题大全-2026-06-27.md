- **位置**：[tavern-compat.js:3570-3573](file:///workspace/js/tavern-compat.js#L3570-L3573)
- **复现条件**：
  1. 第一轮 AI 输出：`pcIdentity.content = "姓名:张三"`（英文冒号 `:`）
  2. 第二轮 AI 输出：`pcIdentity.content = "姓名:李四"`（仅值变化）
  3. `split('：')` 对英文冒号无效，整个字符串作为单段

- **根因**：`split('：')` 只识别中文全角冒号，未考虑 AI 输出中常见的英文半角冒号
- **修复方案**：

```javascript
// 修复：同时识别中英文冒号
var key = String(fact.content).split(/[:：]/)[0].trim();
var idx = list.findIndex(function(a) {
    if (!a || !a.content) return false;
    if (a.content === fact.content) return true;
    return a.content.split(/[:：]/)[0].trim() === key;
```

### P0-2 `RegexManager.applySingleScript` 无 try-catch，单个非法正则中断整个 apply 流程 ★

- **位置**：[modules.js:3285](file:///workspace/js/modules.js#L3285)
- **复现条件**：
  1. 用户在正则脚本编辑器输入 `"[a-Z+"`（语法错误：未闭合字符类 + 范围倒置）
  2. `_detectReDoS`（[modules.js:3280](file:///workspace/js/modules.js#L3280)）不检测语法合法性，只检测 ReDoS 模式，通过
  3. `new RegExp("[a-Z+", flags)` 抛 `SyntaxError: Range out of order in character class`
  4. 异常冒泡到 `applyScripts` 循环外
  5. 后续 10 个合法脚本全部不执行，AI 输出文本未经过任何正则处理
- **影响**：一个用户错误输入中断所有正则脚本，包括预设脚本（如清理 thinking 标签）
- **根因**：ReDoS 防护存在但语法错误未独立 try-catch，`applyScripts` 批量调用未对每个 script 单独包裹
- **修复方案**：

```javascript
applySingleScript: function(script, text) {
    // ... 前置检查、ReDoS 防护
    var regex;
    try {
        regex = new RegExp(regexBody, flags);
    } catch (e) {
        console.warn('[RegexManager] 正则脚本语法错误，已跳过: "'
            + regexBody.substring(0, 50) + '" 错误: ' + e.message);
        if (script) {
            script._lastError = e.message;
            script._errorTime = Date.now();
        }
        return text;
    }
    // ... 后续替换逻辑
},

// applyScripts 批量调用加 per-script try-catch
applyScripts: function(text) {
    var scripts = this.getActiveScripts();
    for (var i = 0; i < scripts.length; i++) {
        try {
            text = this.applySingleScript(scripts[i], text);
        } catch (e) {
            console.warn('[RegexManager] 脚本 #' + scripts[i].id + ' 执行异常，跳过:', e);
        }
    }
    return text;
}
```

### P0-3 `_pruneImportantEvents` 移除 epic 上限导致无界增长 ★

- **位置**：[tavern-compat.js:3230-3238](file:///workspace/js/tavern-compat.js#L3230-L3238)
- **复现条件**：
  1. 长游戏运行 200 回合
  2. AI 每回合返回 1-2 条 `importance >= 9` 的 epic 事件
  3. `_pruneImportantEvents(50)` 中 `keptEpic = epic`（200 条），`normal.slice(0, max(0, 50 - 200)) = []`
  4. 最终 `this.events.length = 200-400`，远超 `maxCount=50`
  5. 每次 `buildSmartInjection` 全量遍历 200+ 条
  6. `saveToStorage` 序列化时体积膨胀，可能触发配额错误
- **根因**：原 15 条上限被注释为"武断截断"删除，但替换策略"epic 全保留 + normal 填充剩余"在 `epic.length > maxCount` 时彻底失效，等价于无上限
- **修复方案**：

```javascript
_pruneImportantEvents: function(maxCount) {
    if (!this.events || this.events.length <= maxCount) return;
    this._recalcEventDecayScores(this.currentTurn);
    var epic = this.events.filter(function(e) { return e.importance >= 9; });
    var normal = this.events.filter(function(e) { return e.importance < 9; });
    epic.sort(function(a, b) { return b.decayScore - a.decayScore; });
    normal.sort(function(a, b) { return b.decayScore - a.decayScore; });
    
    // 修复：epic 上限为 maxCount 的 60%，normal 占 40%
    // 既保留重要事件，又避免 epic 无界增长
    var epicBudget = Math.max(5, Math.floor(maxCount * 0.6));  // 至少 5 条 epic
    var keptEpic = epic.slice(0, Math.min(epic.length, epicBudget));
    var keptNormal = normal.slice(0, maxCount - keptEpic.length);
    
    this.events = keptEpic.concat(keptNormal)
        .sort(function(a, b) { return (a.turn || 0) - (b.turn || 0); });
},
```

### P0-4 `MemoryManagerUI.saveCharacter` 双写 tables 与 Mutator，顺序敏感 ★

- **位置**：[tavern-compat.js:4250-4267](file:///workspace/js/tavern-compat.js#L4250-L4267)
- **复现条件**：
  1. UI 编辑角色 "张三" → 改名为 "李四"
  2. 步骤 a：`delete gm.tables.characters['张三']` + `gm.tables.characters['李四'] = _newCharData`
  3. 步骤 b：`CharacterMutator.replaceCharacter('张三', _newCharData)` 内部从 StateManager 读取，但 StateManager 中此时仍是旧数据 "张三"
  4. 若 `replaceCharacter` 内部依赖 `gm.tables.characters[oldName]` 作为源数据，已被步骤 a 删除 → 读到 undefined → 异常或写入空数据
  5. 中途异常时 `gm.tables` 已改但 `StateManager.entities` 未改，后续 `buildSmartInjection` 读到不一致状态

  - 文档 §3790-3801 注释明确说明这是"两套写入路径"，但未解决，仅记录
  - `GameMemory.tables` 是 legacy 数据源，`StateManager.entities` 是新数据源
  - Mutator 设计为单一入口，但 UI 仍绕过 Mutator 直接写 legacy
- **影响范围**：`saveCharacter`、`saveItem`、`saveLocation` 等同模式方法都受影响
- **修复方案**：单一写入入口

### P0-5 `base.css .hidden !important` 与 `.app-loading` 过渡冲突 ★

- **位置**：[base.css:768-770](file:///workspace/css/base.css#L768-L770) + 加载指示器规则

```css
/* base.css */
.hidden { display: none !important; }
.app-loading--hidden {
    opacity: 0;
    pointer-events: none;
    /* 不加 !important，让 transition 生效 */
}
```
