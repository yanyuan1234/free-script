### P0-1 ⭐⭐⭐ 永久事实区（permanentFacts）5 写入入口 + 3 schema 形态

- **位置**：`js/tavern-compat.js:3098` `addWorldAnchor` + `3740` `upsertPermanentFact` + `3805` `setPermanentFact` + `4390` `saveNewPermanentFact` + `4414` `savePermanentFact`
- **问题代码**（节选）：
  ```js

  self.permanentFacts[key].push(anchor);
  // 3740 upsertPermanentFact（schema B）— 缺 importance
  list.push({ content, locked, source, createdTurn, keywords? });
  // 3805 setPermanentFact（schema C，覆盖语义）— 缺 importance

  ```
- **酒馆 API 对齐**：酒馆 `worldInfoUpdate(entry)` / `getWorldInfo(bookId)` 单一 schema 单一入口。当前 5 入口 3 schema 形态 2 语义（累积 vs 覆盖）= 维护噩梦 + 字段错位 + `importance` 字段仅 schema A 有 → `buildInjection` 第 3127 行"按 importance 升序淘汰"对 schema B/C 写入的条目永远按 0 排序，**会被优先淘汰**。

- **风险评估**：**极高**。导入后导出的酒馆正线预设（用 `<worldInfo>` 写 `npcProfiles`）全部丢 importance 字段，buildInjection 排序错位。

### P0-2 ⭐⭐⭐ 正则引擎 `placement` 过滤是空 if 块

- **位置**：`js/tavern-compat.js:5742-5749`
- **问题代码**：
  ```js
  // ── placement 过滤（月读格式） ──
  // placement: [1] = user input, [2] = AI output
  const placement = script.placement || [];
  if (placement.length > 0) {
      // 1 = 用户输入侧, 2 = AI输出侧
      // 如果当前不在placement范围内则跳过
      // 默认都执行（如果没有placement限制）
  }
  // ⚠️ if 块为空，实际什么都没做
  ```
- **酒馆 API 对齐**：酒馆正则 `placement: [1,2] / [2]` 是核心机制，**果实/月读预设大量使用**（例如只改写用户输入、不改写 AI 输出）。当前实现 = 所有正则都会在用户输入 + AI 输出两阶段都跑，与酒馆行为不一致。
- **修复方案**：
  ```js
  execute(text, scripts, options = {}) {
      const { currentPlacement = 2 } = options;  // 默认 AI 输出
      for (const script of scripts) {
          if (!script) continue;
          if (script.disabled === true || script.enabled === false) continue;
          const placement = script.placement || [];
          if (placement.length > 0 && !placement.includes(currentPlacement)) continue;  // ✅ 实际过滤
          // ... 后续
      }
  }
  // processResponse 传 currentPlacement: 2；processUserInput 传 currentPlacement: 1
  ```
- **风险评估**：**极高**。果实/月读预设的"只改写用户输入"正则**双向都跑**，可能把 AI 输出当用户输入再改写一次，破坏剧情。

### P0-3 ⭐⭐⭐ `addQuest` 在 GameMemory 与 QuestMutator 各一份，AI 标签走 GameMemory 版**不写 StateManager**

- **位置**：`js/tavern-compat.js:1213` `<mem type="quest">` 标签 + `3178` `GameMemory.addQuest` + `js/state/mutators/quest-mutator.js:110` `QuestMutator.addQuest`
- **问题代码**：
  ```js
  // tavern-compat.js:3178 GameMemory 版 — 只 push 数组，不写 StateManager
  addQuest: function(quest) {
      if (!quest || !quest.title) return null;
      if (this.quests.some(function(q) { return q && q.title === quest.title && q.status === 'pending'; })) return null;
      if (!quest.createdTurn) quest.createdTurn = this.currentTurn;
      this.quests.push(quest);  // ← 不写 StateManager
      return quest;
  }
  // state/mutators/quest-mutator.js:110 QuestMutator 版 — 写 StateManager
  addQuest(quest, options) { ... StateManager.set('entities.quests', ...); }
  ```
- **酒馆 API 对齐**：酒馆/酒馆助手对 quest 类数据是单点 schema + 单点 storage。当前两条路径 schema 略不同（GameMemory 用 `title/createdTurn/resolvedTurn`，QuestMutator 用 `title/status/content`），**AI 标签 `<mem type="quest" action="add">` 走的是 GameMemory 版（不写 StateManager）**，UI 走的是 QuestMutator 版，**两条路径写入的字段不同**。重启后 `gameState.currentQuests`（StateManager 同步出来的）会缺一部分。
- **修复方案**：
  1. 删 `GameMemory.addQuest`（3178-3186）整段。
  2. 改 `<mem type="quest">` 标签（1213-1214）走 `QuestMutator.addQuest`：
  ```js
  } else if (type === 'quest') {
      if (action === 'add' && innerContent) {
          if (typeof QuestMutator !== 'undefined' && QuestMutator.addQuest) {
              QuestMutator.addQuest({ title: innerContent, status: 'pending', type: 'quest' });
          }
      } else if (action === 'resolve' && innerContent) {
          if (typeof QuestMutator !== 'undefined' && QuestMutator.resolveQuest) {
              QuestMutator.resolveQuest(innerContent, 'resolved');
          }
      }
  }
  ```
- **风险评估**：**极高**。AI 持续输出 `<mem type="quest">` 标签产生的任务**重启后丢失**，玩家投诉"任务为什么不见了"无法复现。

### P0-6 ⭐⭐⭐ `core.js:1176+1212` `isModelFailed` key 格式不匹配 → 酒馆助手"轮换模型"语义失效

- **位置**：`js/core.js:1176-1183` `_markModelFailed` 写 + `1212-1226` `isModelFailed` 读 + `js/phone-ui.js:5323/5711/5897` 调用方
- **问题**：`_markModelFailed` 用 `key = slot + '|' + cfg.model` 复合 key 存储（避免两 slot 同模型互相误判），但 `isModelFailed(modelName)` 仍用裸 model 名查询。phone-ui.js 3 处调用 `isModelFailed(cfg.model)` 传入 `"gpt-4o"`，而 `_failedModels` 里存的是 `"0|gpt-4o"`，**查找永远失败**。`isModelFailedForSlot`（1195）已正确构造复合 key 但**零调用**（死代码）。
- **酒馆 API 对齐**：酒馆助手的"轮换模型"（`/rotate-model` slash command / 失败自动跳下一档）依赖 `isModelFailed` 决定是否跳过当前模型；key 不匹配意味着酒馆的轮换语义不生效。

- **风险评估**：**极高**。失败模型追踪完全失效，每次失败都会重试同一模型，浪费配额 + 玩家每次都看到同一错误。

### P0-8 ⭐⭐⭐ `game.js:3975` `data-args` 单引号属性注入 XSS

- **位置**：`js/game.js:3974-3975`
- **问题代码**：
  ```js
  return '<button class="npc-chat-choice" type="button" data-action="selectNpcChatChoice" data-args=\'' + JSON.stringify([ch]) + '\'>' + escapeHtml(ch) + '</button>';
  ```
- **问题**：`data-args` 用单引号包裹属性值，`ch` 是 AI 返回的 NPC 聊天选项文本。`JSON.stringify` 只转义 `"`、`\`、控制字符，**不转义单引号**。若 AI 返回 `ch = "x'><img src=x onerror=alert(1)>"`，HTML 变为 `data-args='["x'><img src=x onerror=alert(1)>"]'`，首个 `'` 截断属性，后续 `<img>` 注入 DOM。可见文本经 `escapeHtml(ch)` 安全，但 `data-args` 未转义。
