### P0-1 ⭐⭐⭐ `phone-ui.js:5614` `newCancelBtn` 作用域外引用（ReferenceError）

- **位置**：[phone-ui.js:5570](file:///workspace/js/phone-ui.js#L5570)（声明）+ [phone-ui.js:5614](file:///workspace/js/phone-ui.js#L5614)（外部引用）
- **代码**：
  ```js
  // 5568：bindFresh 回调开始
  bindFresh('btnTestApiDetail', 'click', async function() {
      var newTestBtn = this;
      var newCancelBtn = document.getElementById('btnCancelTestApi');  // 5570：声明在回调内部
      ...
  });                                          // 5612：回调到此结束

  newCancelBtn.addEventListener('click', function() {   // 5614：作用域外引用！
      ...

  ```
- **问题**：`var newCancelBtn` 仅在 `bindFresh` 的回调函数内部（5568-5612）声明，而 5614 的 `newCancelBtn.addEventListener(...)` 在该回调**外部**，此时 `newCancelBtn` 已超出作用域。读取未声明变量必然抛 `ReferenceError: newCancelBtn is not defined`。
- **根因**：06-30 报告 P1-2 修复 `_testAbortCtrl` 闭包逃逸时，把 controller 从函数闭包改为挂到 DOM 节点（`newTestBtn._testAbortCtrl`），同时把 `var newCancelBtn` 一起移进了回调，但 5614 的外部 `addEventListener` 引用未同步迁移。
- **影响链**：`showApiDetail` 执行到 5614 即抛错中断，导致 5614 之后的**全部绑定**未执行：
  - 取消测试按钮（5614）失效
  - 复制按钮（5628）、删除按钮（5650）、tab 切换（5667）、获取模型列表（5686）、失败模型列表（5744）、返回（5770）、刷新（5779）、密码切换（5813）**全部无监听器**
  
  而 5533 `UI.showModal` 与 5537/5555/5568 三个 `bindFresh`（保存/设为当前/测试）在 5614 之前已执行，故弹窗能弹出、这三个按钮能用——这解释了为何该 bug 未被立即察觉。
- **当前状态**：🆕新发现（P1-2 修复的回归 bug）
- **修复方案**：在 `showApiDetail` 顶部（约 5393 后）补一行：
  ```js

  ```
  并删除 5570 回调内的重复声明（保留 5573/5609/5624 的引用即可）。或把 5614 的绑定也包进 `bindFresh('btnCancelTestApi', 'click', ...)`。
- **风险评估**：**极高**。API 详情弹窗的复制/删除/tab/获取模型/返回/刷新/密码切换 8 个按钮静默失效，玩家无法删除/复制 API 配置、无法获取模型列表。

#### P1-1 `core.js:1181+1212` `isModelFailed` key 格式不匹配，失败模型追踪失效
- **位置**：[core.js:1176-1183](file:///workspace/js/core.js#L1176)（`_markModelFailed` 写）+ [core.js:1212-1226](file:///workspace/js/core.js#L1212)（`isModelFailed` 读）+ [phone-ui.js:5323](file:///workspace/js/phone-ui.js#L5323)、5711、5897（调用方）
- **问题**：`_markModelFailed` 用 `key = slot + '|' + cfg.model` 复合 key 存储（避免两 slot 同模型互相误判），但 `isModelFailed(modelName)` 仍用裸 model 名查询。phone-ui.js 3 处调用 `isModelFailed(cfg.model)` 传入 `"gpt-4o"`，而 `_failedModels` 里存的是 `"0|gpt-4o"`，查找永远失败。`isModelFailedForSlot`（1195）已正确构造复合 key 但**零调用**（死代码）。
- **后果**：失败标记被正确记录（`_markModelFailed` 正常）+ `getFailedModels()` 能正确返回（遍历所有 key 并 split），但"单个模型是否失败"的实时查询失效——用户看不到失败模型的 ⚠️ 提醒，误以为所有模型正常。
- **当前状态**：🆕新发现
- **修复方案**：phone-ui.js 3 处 `isModelFailed(cfg.model)` 改为 `isModelFailedForSlot(slotIdx)`（死代码复活）；或 `isModelFailed` 改为遍历 `_failedModels` 的 key 做后缀匹配。
- **风险评估**：高（用户感知最强，但游戏不阻断——`tryWithFallback` 的轮换仍工作）。

#### P1-2 `game.js:3975` `data-args` 单引号属性注入 XSS
- **位置**：[game.js:3974-3975](file:///workspace/js/game.js#L3974)
- **代码**：
  ```js
  return '<button class="npc-chat-choice" type="button" data-action="selectNpcChatChoice" data-args=\'' + JSON.stringify([ch]) + '\'>' + escapeHtml(ch) + '</button>';
  ```
- **问题**：`data-args` 用单引号包裹属性值，`ch` 是 AI 返回的 NPC 聊天选项文本。`JSON.stringify` 只转义 `"`、`\`、控制字符，**不转义单引号**。若 AI（或被 prompt 注入的 AI）返回 `ch = "x'><img src=x onerror=alert(1)>"`，则 HTML 变为 `data-args='["x'><img src=x onerror=alert(1)>"]'`，首个 `'` 截断属性，后续 `<img>` 注入 DOM。可见文本虽经 `escapeHtml(ch)` 安全，但 `data-args` 未转义。注释"无需手动 escapeAttr"是错误判断（仅对双引号属性成立）。
- **当前状态**：🆕新发现
- **修复方案**：`data-args` 改双引号 + `escapeAttr(JSON.stringify([ch]))`；或用索引引用：`data-choice-idx="i"`，把 choices 存到模块变量，委托时按索引取。
- **风险评估**：高（AI 输出可被世界设定/私聊内容污染，构成存储型 XSS）。

#### P1-5 `preset-manager.js:45` `load()` 过滤逻辑写反，保留 null 预设
- **位置**：[preset-manager.js:45](file:///workspace/js/modules/preset-manager.js#L45)
- **代码**：
  ```js
  this.presets = arr.filter(function(p) { return !p || !p._isBuiltin; });
  ```
- **问题**：意图是「过滤掉内置预设」。但 `!p || !p._isBuiltin` 对 `p=null` 求值得 `true`（因为 `!null` 为真），**null 反而被保留**。正确写法应是 `p && !p._isBuiltin`。若 localStorage 中混入 null/undefined 元素（旧版本残留、手动改库），它们会留在 `this.presets` 里，后续 `renderPresetList` 的 `preset.name` 会抛 `TypeError`。
- **当前状态**：🆕新发现
- **修复方案**：`this.presets = arr.filter(function(p) { return p && !p._isBuiltin; });`
- **风险评估**：中（正常数据不会出现 null，但一旦出现会导致预设面板整体渲染崩溃）。
