### 1.3 部分/完全误判项（关键发现）

> **本节是本报告最高价值的产出之一**：经实际代码 Read 验证，识别出 4 项原 P0 是部分或完全误判。

#### 误判 1：P0-6 isModelFailed key 格式不匹配 → **部分误判**
- **统筹版 1 P0-6 描述**：`isModelFailed(modelName)` 仍用裸 model 名查询，而 `_failedModels` 里存的是 `"0|gpt-4o"`，**查找永远失败**
- **代码验证**（`js/core.js:1217-1247`）：
  ```js
  isModelFailed(modelName) {
      if (!modelName) return false;
      var record = null;
      var matchedKey = null;
      // 精确匹配
      if (this._failedModels[modelName]) {
          record = this._failedModels[modelName];
          matchedKey = modelName;
      } else {
          // 模糊匹配：遍历所有 slot 的复合 key 做后缀匹配
          for (let k in this._failedModels) {
              var sepIdx = k.indexOf('|');
              var mName = sepIdx >= 0 ? k.substring(sepIdx + 1) : k;
              if (mName === modelName) { matchedKey = k; record = this._failedModels[k]; break; }
          }
          if (!matchedKey) return false;
      }
      // ... 24小时过期机制 ...
  }
  ```
- **真实情况**：函数**有 fuzzy match 兜底**（1225-1233 行），传入裸 model 名时遍历 `_failedModels` 找后缀匹配，**查找不会永远失败**。风险是"任一 slot 失败即视为整模型失败"，对 UI 提醒用途可接受，对 fallback 切换不准确
- **结论**：报告说"完全失效"是错的。**降级为 P1-46（新编号）**：建议 `isModelFailed` 接受 `(slot, modelName)` 双参数显式消除歧义
- **修复风险**：**极低**

#### 误判 4：P0-10 worldinfo atDepth 去重不命中 → **部分误判**

### 遗漏项 M-1：phone-ui.js 多处 setTimeout 残影

- **位置**：
