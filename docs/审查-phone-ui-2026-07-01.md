## 1. P0 - 严重 Bug

### P0-1 【newCancelBtn 作用域外引用导致 8 个按钮静默失效】

**位置**: `phone-ui.js:5270, 5448, 5492`

**代码片段**:
```js
// 5270 顶部声明
var newCancelBtn = document.getElementById('btnCancelTestApi');
...
// 5448 重新赋值（无 var，赋值给外层 var）
newCancelBtn = document.getElementById('btnCancelTestApi');
...
// 5492 注册 click
newCancelBtn.addEventListener('click', function() { ... });
```

**Bug 根因**:
- `var newCancelBtn` 函数级提升（hoisting），在 `showApiDetail()` 第一次调用时绑定。
- 但 `showApiDetail` 入口处的 `btnCancelTestApi` **不一定存在于 DOM**（只有切换到「测试」tab 才会渲染该按钮）。
- 若第一次进入页面时该按钮不存在 → `newCancelBtn` 为 `null` → `newCancelBtn.addEventListener` 直接抛出 **TypeError**。
- TypeError 中断当前函数执行 → 后续 8+ 个事件绑定（btnCopyApi, btnDeleteApi, apiDetailBack, apiDetailRefresh, tab 切换, fetchModels 等）**全部未生效**。

**酒馆UI对齐说明**:
- 酒馆助手面板在 SPA 视图切换时会重新渲染 DOM，**绝不会用外层 var 持有子视图元素引用**。
- 应改用 `data-action` + 事件委托，每次进入视图都重新 `querySelector` 一次。

**修复方案**:
```js
// 修复前
var newCancelBtn = document.getElementById('btnCancelTestApi');
...
newCancelBtn = document.getElementById('btnCancelTestApi');
newCancelBtn.addEventListener('click', function() { ... });

// 修复后：每次进入 showApiDetail 重新查询并即时使用
var cancelBtn = document.getElementById('btnCancelTestApi');
if (cancelBtn) {
    cancelBtn.addEventListener('click', function() { ... });
}
```

### P0-2 【finally 块 newCancelBtn.style.display 无 null 守卫】

**位置**: `phone-ui.js:5487`

**代码片段**:
```js
} finally {
    newCancelBtn.style.display = 'none';  // 5487
}
```

**Bug 根因**:
- `newCancelBtn` 在 `try` 之前的赋值上挂空指针（见 P0-1）。
- finally 块没有 null 守卫 → 测试接口请求异常时，TypeError 会被吞进 finally 内层抛出。
- 导致调用栈中断、UI.toast 无法触达用户。

**修复方案**:
```js
} finally {
    if (newCancelBtn) newCancelBtn.style.display = 'none';
}
```

| 行号 | 调用点 |

**重复模式**: 实际上 `renderEmptyState()` 已经统一（864 行），11 处调用点本身不重复 — **真正的重复在于**：部分空状态仍然走 `<div class="empty-state-icon">...</div>` 内联模板（1772/3082/3515/7286 等），没走 `renderEmptyState`。

**修复方案**:
- 强行 100% 走 `renderEmptyState(text, iconType)`，删除内联模板。

### P1-2 【errorListEl.innerHTML 内联模板未走 escapeHtml 统一处理】

**位置**: `phone-ui.js:5379-5389`

**代码片段**:
```js
errorListEl.innerHTML = errorLogs.map(function(log) {
    var timeStr = _formatLogTime(log.time, 'full');
    return '<div class="pearl-card" style="padding:12px;border-left:3px solid #e74c3c;">' +
        '<div style="display:flex;justify-content:space-between;font-size:12px;color:var(--text-secondary);margin-bottom:6px;">' +
        '<span>' + escapeHtml(log.model) + '</span><span>' + timeStr + '</span></div>' +
        '<div style="font-size:13px;color:#e74c3c;word-break:break-all;">' + escapeHtml(log.error || '未知错误') + '</div></div>';
}).join('');
```

**问题**:
- `log.model` 和 `log.error` 走了 `escapeHtml`，**但 `timeStr` 没走**。
- `timeStr = _formatLogTime(...)` 通常是 `HH:MM:SS` 格式，安全；但 `_formatLogTime` 实现版本多了之后可能输出包含 `<` 的内容，存在 XSS 隐患。
- 整个拼接用内联字符串 + `.style=""` 散在 JS 中，难以审计。

**酒馆UI对齐说明**:
- 酒馆助手错误日志走统一的 `<Template>` 元素 / `sanitizeHtml` 包装。
- 内联 style + 内联 HTML 拼接是 CSP 不友好的反模式。

**修复方案**:
```js
// 走 renderEmptyState 或新建 renderErrorLogItem(log)
// 统一 sanitize
'<span>' + escapeHtml(timeStr) + '</span>'
```

### P1-3 【18 对 cloneNode + replaceChild 反模式】

**位置**: `phone-ui.js` 大量分布

**问题**:

**酒馆UI对齐说明**:

**修复方案**:
- 全面替换为 `bindFresh(id, 'click', handler)`。

## 3. P2 - 死代码 / 重复实现

## 4. P3 - 风格与一致性

### P3-1 【var / let / const 混用】

- phone-ui.js 全文 `var`，utils.js 全文 `var` / `const` 混用。
- 建议统一：内部变量 `let`，常量 `const`。

### P3-2 【onclick= 内联事件未清理】

经 grep `onclick\s*=` 在 phone-ui.js 中已为零，但 `onmouseover|onerror|onmouseout` 等也存在个别内联属性。

### P3-3 【renderMomentsPage 30+ 次 html += 累加】

- 应改为 `Array.push + join('')` 模式，减少 V8 反复 reallocate 字符串。

### P3-4 【NpcList 命名不一致】

`renderNpcPage`（7227）/ `renderNpcList`（7232 别名）同时存在，导致 4 处调用点不统一。建议统一为 `renderNpcList` 或 `renderNpcPage`，删除别名。
